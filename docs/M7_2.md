## 通用控制逻辑

`agent.runner.run_agent` 是 CLI 与新评估的门禁入口，先用正式工具独立验证原始候选。
全部 required checks 通过时返回 `NO_REPAIR_NEEDED / no_repair_needed`、`agent_invoked=false`，
无模型调用、无 patch、无 probe。Capability probe 可通过 `run_probe` 独立执行。
`AgentLoop.run` 保留为低层已触发任务的继续执行接口，供 M5/M6 隔离测试与内部调用。

成功 finish 要求当前 candidate/context 的全部正式证据通过，且 regression guard 不阻断。
不满足时返回 `FINISH_PRECONDITION_FAILED`，含 missing/failed/stale、当前版本和可选工具；
状态机继续把它交给模型。宿主不自动按顺序补做检查，相同无效 finish 沿用警告和 no_progress 终止。

`success=false`、`outcome=failure` 或 `outcome=abandoned` 明确结束为 FAIL。
旧 success / conclusion 调用仍有效；明确失败优先，不能因已有通过证据被升级为 PASS。
无 outcome 的旧成功 finish 同样必须满足证据要求。

每个工具结果的 `evidence.validation_state` 包含：

```json
{
  "candidate_version": "2:<sha256>",
  "required_checks": {
    "execute": "passed",
    "validate_packages": "missing",
    "validate_apis": "failed",
    "run_pytest": "stale"
  },
  "ready_to_finish_successfully": false,
  "regression_blocked": false
}
```

沿用既有工具名与版本格式，不额外增加 syntax 正式检查。语法仍在 patch 和原验证边界检查。
`check_results` / `check_result_contexts` 保留宿主历史证据；patch 清空有效 passed checks，历史显示 stale。
旧记录不能授权新候选通过。完整输出保存在 artifact，模型 observation 继续受长度限制。

## 统计口径

- 最终通过、strict_rescue、control 保持和虚假成功分子沿用 `interview_metrics.py`；该文件不改。
- 仅触发修复的任务进入正式协议和任务 probe 分母，门禁跳过的 control 不算协议失败。
- 另列“虚假成功 / 全部 15 任务”；原“虚假成功 / 有成功声明任务”也保留。
- 被拒绝但最终真实通过的 finish 不算最终虚假成功；`rejected_finish_count` 和逐次拒绝轨迹独立保留。
- 平均步骤、调用数、耗时覆盖全部 15 例，control 的步骤和模型调用数为 0。
- 旧 one-shot 的 15 份 artifact 逐字节复用，没有重新推理或择优。
- 24 步、300 秒和工具执行 10 秒不变；新入口将初检计入 300 秒，修复任务最终审核另限 30 秒。
- 未触发的 control 复用初检证据，与原 one-shot control 的处理一致。

## 复现

```powershell
$env:PYTHONPATH='src'
& "$env:LOCALAPPDATA/Programs/Ollama/ollama.exe" ps
.venv/Scripts/python.exe -m pytest -ra
.venv/Scripts/python.exe -m ruff check .
.venv/Scripts/python.exe -m evaluation.m72_validation --output-dir results/m72
.venv/Scripts/python.exe -m evaluation.interview_benchmark infrastructure --output-dir results/m72/infrastructure
.venv/Scripts/python.exe -m evaluation.m72_report --output-dir results/m72
```
