# M5：原生工具协议与稳定运行

本阶段复用原 AgentState、ToolRegistry、AgentLoop、patch 和持久化实现；保留
one-shot pipeline、执行器和历史评估。开工时相关源码、README、schemas、测试及
engineering sanity/M4 记录已检查，基线为 90 项测试通过。本阶段未使用 Git，
无法凭版本控制区分先前改动的归属；当前文件内容作为基线，保留既有用户产物。

## 契约与处理选择

- `AgentModel.decide(messages, tools, timeout_seconds=...) -> AgentDecision` 单步返回
  `tool_call`、`text`、`protocol_error` 或 `provider_error`，携带原始公开响应、
  error_code/message，以及简短 `decision_summary`。旧 `thought` 字段兼容保留，
  不读取模型隐藏推理。
- 只承认原生 tool_calls 中恰好一个合法调用。content 中的 JSON/Markdown 仍为文本；
  多调用、未知工具、缺失参数及类型错误成为协议 observation，等待下一步选择。
- 后端错误与协议错误分开；工具异常返回结构化 ToolResult.error。
- finish 保留旧 conclusion 调用兼容性，新 prompt 要求 success 布尔声明。
  `finish(success=true)` 不足以证明 PASS。宿主核对 required_checks 的真实通过证据，
  且候选版本和验证上下文版本必须同时匹配，否则记录 false_success。
- 保留原终止枚举名称，不静默重命名历史结果。预检失败新增固定原因
  MODEL_TOOL_PROTOCOL_UNSUPPORTED；网络/凭据错误导致预检失败时能力标为 unknown。
- 正式验证可配置 required_checks，默认仍为包/API/执行，以及有测试时的 pytest。
  为保留写盘保护，`--apply` 后仍执行原有完整复验；自定义较少检查不能绕过此保护。
- patch 的 hunk count、路径和语法规则沿用 M3，不在 M5 扩大容错或多文件支持。

| 最终状态 | termination_reason | 含义 |
| --- | --- | --- |
| PASS / FAIL | finish | 显式结束，宿主证据决定结果 |
| FAIL | MODEL_TOOL_PROTOCOL_UNSUPPORTED | 预检未通过；正式轨迹为空 |
| INCOMPLETE | max_steps | 用完正式决策步数 |
| INCOMPLETE | global_timeout | 全局期限覆盖预检、模型和工具 |
| INCOMPLETE | protocol_errors | 连续协议错误达到配置阈值 |
| INCOMPLETE | no_progress | 同一调用重复，警告后再次重复 |
| ERROR | model_error | 正式运行后端异常 |
| ERROR | write_failed / rollback_failed | 原有持久化失败结果 |

## 预检

预检复制模型到独立有期限的进程，不接收 AgentState、不分发真实工具，独立记录
transcript：先调用 probe_echo，再读取随机 challenge observation 并正确回传，最后
调用 finish。正式候选、计数、缓存、证据和轨迹不被预检改动。预检耗时计入全局预算。

只缓存成功结果，键包含 provider/model 配置身份、协议版本及正式工具 schema。
缓存只活在当前进程；CLI 独立进程之间不共享。`--no-probe-cache` 禁用，Python
`depguard.agent.probe.clear_probe_cache()` 清空。跳过预检不会声称能力已经支持。

示例运行预检输出节选：

```json
{
  "status": "passed",
  "stage": "complete",
  "reason": "Native calls, observation followup and finish verified",
  "model_response_kind": "tool_call",
  "cached": false
}
```

## 三个模型后端

- OllamaAgentModel 继续接受 Ollama 原生工具响应，不影响原 OllamaRepairModel 单次修复。
- ScriptedTestModel 是显式测试后端，预检脚本与正式脚本独立；expect 可断言上一条
  observation 的工具、状态、passed 和内容。它不伪造真实验证结果。
- CloudToolCallingModel 使用标准库 HTTP 和原生 Chat Completions 工具协议。
  默认 DeepSeek HTTPS endpoint，model_name 必须显式设置；兼容端点可配置。
  原生 call ID 和 tool_call_id 保持关联，function.arguments 字符串只在原生调用内解析。
  DeepSeek 默认关闭 thinking，其他端点不发送该供应商专属字段。未实现需要回传隐藏
  reasoning 的模式。参考 [DeepSeek 原生工具文档](https://api-docs.deepseek.com/guides/tool_calls/)。
  密钥只从配置指定的环境变量读取；错误不输出 HTTP 响应正文或请求头，响应中的同值
  凭据也会脱敏。URL 禁止嵌入凭据。无需新增 SDK 依赖。

云测试使用可注入 mock HTTP transport，覆盖请求 schema、ID 回传、预检、文本、
多调用、参数错误、401、缺失凭据和脱敏。本阶段没有真实云调用，不能据此声称任何
云模型真实通过预检或具有更好的修复率。

## CLI 与配置

在项目根目录、安装项目依赖的 Python 环境中运行：

```powershell
python -m depguard.cli agent --config configs/m5_scripted.json --code-file examples/m5/input.py --test-file examples/m5/test_input.py --requirement "Return three as result." --trajectory-output results/m5/scripted_run.json
```

云调用须自行设置 `DEEPSEEK_API_KEY` 环境变量并明确选择模型：

```powershell
python -m depguard.cli agent --config configs/m5_cloud.json --agent-model YOUR_NATIVE_TOOL_MODEL --code-file examples/m5/input.py --test-file examples/m5/test_input.py --requirement "Return three as result." --trajectory-output results/m5/cloud_run.json
```

| CLI 参数 | agent 配置字段 | 默认值 |
| --- | --- | --- |
| --agent-provider | provider | ollama |
| --agent-model | model_name | Ollama qwen2.5-coder:7b；云须指定 |
| --base-url | cloud.base_url / ollama.base_url | 后端默认地址 |
| --script | script | 无，scripted 必填 |
| --max-steps | max_steps | 20 |
| --timeout | timeout_seconds | 180 秒 |
| --protocol-error-limit | protocol_limit | 3 |
| --recent-steps | recent_steps | 6 |
| --observation-max-length | output_limit | 4000 字符，最少 80 |
| --[no-]capability-probe | capability_probe | true |
| --[no-]probe-cache | probe_cache | true |
| --trajectory-output | 无 | 不输出文件 |

CLI 显式值优先。`agent.validation.required_checks` 可指定受支持检查的非空子集。
`execution.timeout_seconds` 控制单次执行预算，同时仍受全局期限约束。云配置的
`agent.cloud.api_key_env` 是环境变量名称，不能放密钥值。`--output` 和
`--trajectory-output` 都保存完整结果，禁止覆盖源/测试输入。默认 dry-run；原
`--apply`、权限 deny、风险策略和全局回滚语义保留。

## 上下文、重试与证据

当前候选、原始哈希、patch、快照、权限、检查和缓存属于外部 state。messages 只是
其投影，不能授权新权限或制造通过证据。保留最近 N 步完整消息对，早期步骤由宿主
生成计数、patch 数和最后失败摘要，不让模型总结。stdout/stderr 在 observation
保留头尾，优先保留错误类型、失败测试、语法错误、patch 错误位置和必要预览。
字符预算不是 token 精确预算；候选和测试本身仍完整提供，因此不是任意大项目支持。

每步保留 step、timestamp、thought、tool_call、tool_result，以及 candidate_version、
decision_summary、observation、raw_result_ref、state_transition、cached。
原始工具输出位于 trajectory 的 tool_result；raw_result_ref 是指向它的 JSON Pointer。
脱敏和丢弃隐藏推理后的公开模型响应存于 raw_response。

指纹包含工具名、规范化参数、候选哈希以及相关外部上下文哈希：输入哈希、测试、
权限、风险策略、执行超时和验证配置。只读成功验证可缓存；执行结果不作为缓存返回。
候选/配置改变、前次基础设施错误或 `--allow-test-rerun` 允许重跑，测试断言失败本身
不属于基础设施错误。连续相同调用达到阈值先给警告，再重复才 no_progress。
