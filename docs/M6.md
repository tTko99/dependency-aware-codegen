# M6：可靠 patch、dry-run、写盘与回滚

## 范围与兼容性

复用 M5 AgentLoop、原生工具调用/预检、ToolRegistry、既有权限与 AST 风险分析、
patch 和 snapshot 实现；不重写模型后端及 one-shot pipeline。本阶段没有任何 Git
操作。历史 M4/M5 产物保留，新演示每次生成独立目录，避免覆盖用户文件。

明确的契约调整：

1. 原候选版本只有内容哈希；M6 改为 `revision:sha256`，JSON schema_version=2，
   另外提供 candidate_revision 和 candidate_sha256。成功 patch 和全局内存 rollback
   使 revision 递增，失败不变；恢复同一代码也不会复用旧验证证据。
2. 行号和 hunk count 不再是拒绝的唯一依据。以正文 context/删除行精确匹配，按 hunk
   顺序寻找唯一位置；不模糊匹配、不用模型行号在多个候选位置中擅自挑选。
3. 无文件头必须显式传 `path`，且与唯一授权源文件一致。既有相关测试增加 path。
   标准头仍是首选。原来要求错误 count 必须失败的测试改为成功规范化测试。
4. 写盘独立核对末步 finish、当前代码/版本、完整检查及上下文版本，拒绝伪造 PASS
   或过期证据。旧持久化测试改为先取得实际工具证据，再测试写盘失败场景。
5. 写后哈希异常与外部并发修改不能可靠区分。为满足“不得覆盖新内容”，自动尝试
   rollback 时若发现既非原始也非最终候选的内容，则保留它和 snapshot，明确返回
   rollback_failed。不是承诺所有异常都能强制恢复。

## Patch 工具

支持标准 unified diff、Markdown diff 围栏，以及显式 path 的无头 hunk。
先解析全部 hunk，在副本上整体应用，再 AST 解析；只有全部成功才更换 candidate。
保留 LF/CRLF 与无末尾换行，规范化 diff 使用缺少换行标记，可再次应用。

错误结果包含 error_code、error_line、最多 4000 字符的 raw_patch、format_example；
语法错误另有 column/context。错误结果保留旧 candidate_version。成功结果包含
normalized_patch/preview、before/after 的版本/哈希/行数和 regression_guard。
规范化 patch 存入 applied_patches，旧候选及操作留在 candidate_history，旧检查失效。

`path_guard` 在 patch 工具和最终持久化内调用，约束单文件 write_scope。拒绝路径
穿越、绝对路径、解析后越界的链接、测试路径、未授权路径、二进制/非 UTF-8 Python
目标，以及 `.git`、虚拟环境、缓存、构建输出和常见敏感文件。路径集合不是完整
秘密识别器，关键边界仍是唯一授权源文件。

拒绝码包括 PATH_OUTSIDE_ROOT、SYMLINK_ESCAPE、TEST_FILE_READ_ONLY、
PATH_NOT_IN_WRITE_SCOPE、BINARY_FILE_UNSUPPORTED。

## 完整性与权限

初始化保存源/正式测试原始字节 SHA-256、真实路径和配置文件 SHA-256。CLI 还核对
配置读取前后哈希，避免读入配置与冻结版本不同。候选变化不会改磁盘原始哈希。
执行/pytest 内部重新检查输入，注册分发也检查；缓存不能绕过权限/哈希。
最终写盘前再次检查。变化分别给出 SOURCE_INTEGRITY_MISMATCH、
TEST_INTEGRITY_MISMATCH、CONFIG_INTEGRITY_MISMATCH，不覆盖外部输入。

权限仍为 read_source、read_tests、execute、write_temp、write_target。CLI 默认不授予
write_target；只有显式 `--apply` 才授予，且宿主最终 PASS 后才能写。配置
`execution.enabled=false` 移除 execute；`--deny-permission` 继续可用。
apply_patch 没有磁盘写入能力，测试文件不在 write_scope。

## 安全扫描与 regression guard

执行前沿用保守 AST 扫描，包含 candidate 及即将运行的正式测试。识别 subprocess、
os.system、eval/exec、文件写、网络写、shutil、import/from alias、可解析 getattr 和
常量字符串拼接（例如 `'sys' + 'tem'`）。无法解析的动态接收对象仍保守拒绝。
风险返回 REQUIRES_SANDBOX 并标 executed=false；旧 mock 模式继续醒目标记，绝不
建立 passed_checks。没有任何风险处理模式会执行命中风险的代码。

轻量 regression_guard 比较原始与最终 AST 和 diff：

- 严重：测试路径写入、新增 pytest skip/skipif/xfail（含导入别名）、删除顶层公开函数
  或类、超过 patch 行数或文件数限制。阻止宿主最终 PASS 与 apply。
- warning：新增不重新抛出的异常处理、常量与可见断言值吻合、原始语法损坏导致无法
  比较完整公开接口。不会把所有常量修复直接认定为作弊。
- 每个成功 patch 的结果及 finish observation 都带结构化证据，进入轨迹。
- `agent.regression_guard.max_patch_lines` 默认 500（净 diff 新增+删除），max_files 默认
  1；须为非负整数。当前仍只授权一个文件，没有多文件 Agent。

这只是启发式检查，不能识别所有作弊或证明语义正确。
**subprocess + 临时目录 + timeout 是进程与时间边界，不是安全沙箱。**

## 写盘与回滚

默认输出 candidate_code、normalized_diff、检查、trajectory 和版本，源文件不变。
CLI 使用方式保留：

```powershell
python -m depguard.cli agent --config configs/m5_scripted.json --code-file examples/m5/input.py --test-file examples/m5/test_input.py --requirement "Return three as result." --trajectory-output results/m6_dry_run.json
```

需要真正写入指定源文件时，在上述命令添加 `--apply`。成功才写源，测试不变。
重新跑已经修好的文件应换适合它的决策脚本；固定 M5 演示脚本预期初始测试失败。

首次实际写盘前保存原始字节 snapshot；候选写到同目录受控临时文件，flush/fsync
后 os.replace；写后检查哈希并重复包/API/执行/pytest。自定义 formal required_checks
仍不能削弱原有完整写后复验。异常或可捕获中断触发 rollback；写入前失败则记录
未写入。原子替换未改变源时，rollback 通过确认原始哈希完成，不做不必要重写。

`persistence.rollback` 字段：attempted、succeeded、failure_reason、restored_sha256。
保留旧 rollback_result 兼容；成功写入且复验通过时清理 snapshot。失败后保留 snapshot
并输出 recovery_path，尤其 rollback 失败时不删除恢复证据。

限制：哈希检查不是 OS 文件锁，仍存在检查到写入的竞争窗口；进程被强制杀死、断电
不能保证执行 Python rollback。保留的原始 `.bak` 可作为人工恢复依据；没有后台恢复
服务，也不承诺自动覆盖未知的外部写入。

## 实际演示证据

运行 `python examples/m6_demo.py`，脚本只在新建的 `results/m6/demo-*` 目录创建演示
源/测试，使用 ScriptedTestModel 选择动作、真实执行 pytest，直接调用宿主持久化函数
便于注入写后错误。CLI `--apply` 另由自动化集成测试覆盖。

本次完整产物：[report.json](../results/m6/demo-nfplu_lv/report.json)。脚本是确定性测试
后端，不计为真实模型救回指标。

**错误 count 安全规范化：**

```diff
--- a/input.py
+++ b/input.py
@@ -88,77 +99,66 @@
-result = 1
+result = 2
```

正文唯一匹配，成功后的头变为 `@@ -1 +1 @@`，状态 success，candidate_revision=1。

**多 hunk 原子失败：** 第一段试图把 result=2 改为 4，第二段查找不存在的 missing=1。
返回 PATCH_CONTEXT_MISSING，第一段不生效，候选仍为 result=2，版本不变。

**dry-run：** M5 的两次 patch/三次 pytest 场景仍在 9 步结束，宿主 PASS，applied=false。
源文件前后 SHA-256 相同：

```text
68833fe50c22a93765392cd3e53b25e8a0c7b74e4730e85425e21da46bd69d5c
```

**成功 apply：** 再从原始输入运行完整验证，applied=true，源变为 result=3，写后四项
验证通过，snapshot_cleaned=true。正式测试哈希保持不变。

**写后失败：** 在独立输入上注入复验异常，最终 ERROR/write_failed，返回：

```json
{
  "attempted": true,
  "succeeded": true,
  "failure_reason": null,
  "restored_sha256": "68833fe50c22a93765392cd3e53b25e8a0c7b74e4730e85425e21da46bd69d5c"
}
```

## 验证结果与剩余限制

完整 `python -m pytest -o addopts='' -q`：195 passed，1 skipped（43.42 秒）；旧 one-shot
及 M5 多轮回归通过。`python -m ruff check .`：All checks passed。唯一 skipped 是
Windows 主机缺少创建真实符号链接权限；另有不需要
该权限的确定性解析后逃逸测试通过。此项为环境限制，不声称真实链接测试已经运行。

没有已知未修复的测试失败。未实现的 Docker/WSL/VM、多文件浏览、任意 shell、隐藏
测试服务、模型生成正式测试、大模型下载和大型 benchmark 均为本阶段明确非目标。
安全扫描和 regression guard 的不完备性、无 OS 文件锁和强杀恢复属于已知设计限制。
