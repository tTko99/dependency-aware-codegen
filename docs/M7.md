# M7：可复核的小型评估与面试说明

## 项目定位

第一版系统使用确定性依赖/API 验证和一次模型修复。升级版将修复过程改为 observation
驱动的工具调用状态机。模型负责选择策略，工具执行受限能力，宿主控制权限、patch
原子性、终止条件和最终验证。

本阶段完成评估框架、冻结数据、真实本地模型比较、基础设施挑战及报告。没有执行
任何 Git 操作；没有重新训练、下载模型、调用真实云模型或改写历史 M4/M5/M6 结果。

## 先检查并复用的基础

- engineering sanity 的 manifest、source_hashes、历史逐例结果：历史 8/8 修复和
  2/2 control 只作回归，不充当困难救回集合。
- controlled evaluation 的 manifest、resolved config、summary：7B 历史预算为每次
  64 token、上下文 4096，结果属于既有受控分布；不与本次 1024 token 结果混算。
- M4 的 sha、file_hashes、one_shot、RecordedRepair 以及逐例 JSON/manifest 模式。
- M5/M6 的 probe、原生模型后端、trajectory、patch、宿主工具、风险/回归检查和
  persistence._atomic_write；新增评估在这些边界上编排，没有建设另一套 Agent。

契约调整：M4 rescue_details 只要求失败 baseline 后最终通过，不满足 M7“第一次
Agent 修复仍失败”的严格定义，因此保留历史函数，新增独立 strict_rescue。旧 one-shot
执行器没有同等 M6 护栏；M7 condition A 使用相同模型的一次完整代码响应，再经过
M6 patch/宿主检查，不拿不等安全边界的旧 pipeline 直接对比。旧 pipeline 只用于
sanity 回归，仍保持兼容。

## 冻结集合

[manifest](../data/interview_eval/manifest.json) 在真实推理前生成并冻结，共 **24 例**：

| 类别 | 数量 | 设计 |
| --- | ---: | --- |
| 困难 | 10 | API/参数与结构、空输入/负值、顺序与不可哈希值、递归深度、输入变异、尾段等 |
| 正确 control | 5 | 从前五个需求的人工参考实现构造，正式测试相同 |
| 安全/越权 | 5 | os alias、文件写、eval、路径穿越、修改正式测试 |
| 生命周期 | 4 | 格式拒绝后纠正、多 hunk 原子失败、语法拒绝、写后故障回滚 |

每例固定 requirement、input.py、test_input.py、reference.py、问题类别、provenance、
write scope、required checks、SHA-256 和类别标记。参考实现不发送给真实模型。
全部人工设计，**不宣称来自自然模型失败，也不预先假设 one-shot 必败**。测试快速、
确定、无网络；安全案例只测试拒绝。没有根据实际结果删除或调整任何案例。
冻结数据含故意缺陷，ruff 不改写这些字节，哈希验证和参考实现宿主测试负责验证。

## 本次真实条件

- 模型：Ollama `qwen2.5-coder:7b`，两组相同 digest：
  `dae161e27b0e90dd1856c8bb3209201fd6736d8eb66298e75ed87571486f4364`。
- 当前环境：Python 3.12.14、Windows 11、Ollama 0.34.1；模型为 7.6B Q4_K_M。
  历史记录使用过 Python 3.13.8、Ollama 0.32.5；不声称新旧环境完全一致。
- 两组相同源、requirement、正式测试及每调用参数：temperature=0、seed=42、top_p=1、
  repeat_penalty=1、1024 token、8192 context。详见 configs/m7_ollama.json。
- 最多 20 个 loop 正式步骤，正式期限 120 秒，每次执行 5 秒；独立最终宿主审计另给
  最多 30 秒。probe 不缓存，因此 15 次分别实测原生协议。
- one-shot 先给完整初始错误证据，只允许一次代码响应；control 初始检查已过则不调用
  模型。loop 自选 action。两组最终都执行 M6 包/API/执行/pytest 和 regression guard。
- 这不是等总 token 实验：loop 若能进入协议，可花更多调用。提示格式、初始诊断方式
  与策略不同；单次种子、小样本和共享机器计时不能支持纯架构因果或性能结论。

| 指标 | 结果 |

| sanity control | 2/2 NO_REPAIR_NEEDED |
| 新集合 one-shot 困难通过 | 8/10 |
| 新集合 one-shot control 保持 | 5/5 |
| one-shot 总体真实通过 | 13/15 |
| Agent 原生协议成功 | 0/15 |
| Agent 流程最终通过 | 0/15 |
| Agent control 未修改 | 5/5 |
| Agent control 流程保持率 | 0/5：probe 失败，未正常 finish；独立检查仍通过 |
| 严格多轮救回 | **0/0，N/A** |
| 原始 one-shot 失败数 | 2 |
| Agent patch 接受率 | 0/0，未产生正式 patch 调用 |
| 模型虚假成功率 | 0/0，未调用 finish 声明成功 |
| 基础设施预期越权拒绝 | 5/5 |
| 基础设施写后失败回滚 | 1/1，恢复 SHA-256 一致 |

**在 0 个 same-model one-shot 失败且成功进入 Agent 协议的案例中，严格多轮救回 0 个；
分母为零，因此不能计算救回百分比。** 不能写成“救回率 0/2”，更不能将 scripted
演示算入救回分子。15 次 probe 均在 first_call 返回文本而非原生 tool_calls。

所有真实运行及 sanity 的源和测试哈希保持不变。Agent 并未把正确代码改坏；control
流程 0/5 与代码未修改 5/5 是不同问题，报告分别列出，不把独立审计升级成正常 finish。

两条真实 one-shot 失败：

- json_names：修正 JSON 参数及列表结构，但仍直接索引 data['users']，对 `{}` 发生
  KeyError。
- stable_unique：恢复顺序但仍依赖 set，对列表元素发生 TypeError: unhashable type。

平均每例耗时 one-shot 约 3.044 秒，loop 约 1.437 秒；后者是在 probe 阶段早退，**不是
多轮更快**。平均模型调用分别约 0.667（control 零调用）与 1（probe）；正式步骤均为
0。输入/输出 token：one-shot 12313/575，loop 3420/255。每组 15 次，不报 p95。
cases.jsonl 的 validation_counts 从证据计算宿主初始/正式/最终检查次数；原始逐例
verification_count 只表示正式 loop 工具验证次数。

## 代表性轨迹与未产生的证据

真实模型未进入工具协议，**没有两条真实多轮救回轨迹可以展示**。报告保留真实 probe
失败，并展示以下明确标记的基础设施轨迹，全部调用真实验证工具但不计模型修复率：

- mean_edges：修正 average→mean 后空输入测试仍失败；接收该 observation 后第二个
  patch 处理空输入，宿主 PASS。
- json_names：只去掉错误参数后结构测试仍失败；第二个 patch 修正输出结构，宿主 PASS。
- patch_format：首次格式被拒绝；脚本核对 PATCH_PARSE_ERROR observation 后重发有效 diff。
- patch_atomic：第二个 hunk 找不到 context，整个 patch 不生效，保留失败证据。

只展示 step、公开 decision summary、tool、observation、candidate version 与结果；
不记录或声称保存隐藏思维链。写后故障注入得到 succeeded=true，复核恢复哈希。
基础设施临时目录会清理，artifact 保留实际哈希/轨迹；其中临时恢复路径不是长期恢复服务。

## 复现命令

在仓库根目录、已安装依赖的 Python 环境执行。输出目录用新的名称；sanity 拒绝覆盖，
比较可在同一目录续跑。设置 PYTHONPATH 后无需改动项目安装。

```powershell
$env:PYTHONPATH='src'
python -m evaluation.interview_benchmark sanity --live --output-dir results/m7_new/sanity
python -m evaluation.interview_benchmark one-shot --output-dir results/m7_new/local
python -m evaluation.interview_benchmark loop --output-dir results/m7_new/local
python -m evaluation.interview_benchmark infrastructure --output-dir results/m7_new/infrastructure
python -m evaluation.interview_benchmark report --output-dir results/m7_new/local --infrastructure-dir results/m7_new/infrastructure --sanity-dir results/m7_new/sanity
```

不带 `sanity --live` 时复验历史修复输出，明确标记 replay，不算真实推理。
相同比较命令再次执行会检查 run identity 和逐例 checksum，跳过已完成 case。配置、
manifest、模型 digest 或环境身份变化时拒绝混入旧 run。每例先原子保存再更新索引，
中断不会丢失其他已完成 artifact；未索引的中断 case 可以重跑。没有筛选 case 的 CLI。

## 不能得出的结论

当前证据没有证明真实模型多轮修复收益：主要阻塞是原生工具协议。预检失败不是 patch
解析失败，也不是安全扫描造成；安全与 rollback 数字只是基础设施挑战，不是模型行为率。
subprocess、临时目录和 timeout 不是安全沙箱，不应执行任意不可信 Python。
当前只适合单文件受控评估，不是完整仓库级编码 Agent。隐藏测试、完整沙箱、多文件、
本地大模型、云平台和自动发布均为非目标；真实云调用与真实救回轨迹未执行/未产生，
没有使用模拟数据补足这些证据。
